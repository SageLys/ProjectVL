# 效果原子参数：契约声明与实际消费核查表

> 核查日期：2026-07-29；契约版本：0.5.0；覆盖 `ATOM_CONTRACT` 全部 34 个原子、全部参数。

## 核查口径

- “消费”要求参数会进入运行时分支、状态、结算、命中或展示；只被类型/校验器读取不算消费。
- 下表中的“通用概率闸门”指 `registry.ts / runEffects()`；除 `stun` 外，触发式效果的显式 `chance` 都在这里消费。`stun.chance` 由 `ATOMS.stun()` 对每个目标独立消费。
- `registry.ts / targets()` 统一消费控制/范围类原子的 `radius`，并遵循 `ctx.radius` 优先。
- “完整”表示每个参数至少存在一条真实消费路径；“上下文差异”表示参数在某些合法路径有意或历史性地不生效，详见末尾缺口清单。

## 缺口与上下文差异（单列）

### A. 未发现新的“全局完全未消费”参数

本轮退役 `mergeRule`、实装 `summon.fireInterval` 与 `groundZone.shape='line'` 后，34 个原子的每个契约参数都至少存在一条实际运行时消费路径。没有发现第四、第五个与前两项同等级的“声明存在但全项目不生效”漂移。

### B. 被动聚合不会执行通用 `chance` 闸门

`getModifiers()` 是高频纯查询，不能掷骰。因此下列原子位于被动聚合路径时，其 `chance` 不生效：

- 纯 modifier 原子：`dropRateMul`、`dropLifetimeMul`、`xpMul`、`expiryConvert`、`thorns`、`breachReduction`、`novaOnBreak`；
- 同时有触发式与被动语义的原子：`beamMorph`、`mortarMorph`、`aura`、`execute`。

这不是本轮新增问题；阶段 1 已按要求只记录、不改变旧卡行为。后续应单独决定：从这些被动契约移除 `chance`，或设计在稳定消费点冻结结果的专用概率参数；不得在 `getModifiers()` 内掷骰。

### C. 历史 modifier 触发器范围仍然不统一

`beamMorph`、`mortarMorph`、`aura` 以及两个新经济原子会显式检查 `binding.trigger === 'passive'`；旧 modifier 分支 `dropRateMul`、`dropLifetimeMul`、`xpMul`、`expiryConvert`、`thorns`、`breachReduction`、`novaOnBreak`、`execute` 不检查，挂到非 `passive` 触发器也会永久聚合。按阶段 1 的零漂移要求，本次仅记录，未修改。

### D. 合法路径中的参数裁剪

- `pierce` 消耗态固定为巨型贯穿弹：使用 `width`、`damageMul`、`damageRetention`，但不使用装备弹道语义的 `count`、`rampPerPierce`。
- `aura` 被动态是常驻圆形光环：不使用临时区域语义的 `duration`、`shape`、`innerRadius`、`color`；消耗态不使用 `radiusRatioOfRange`。
- `dot` 嵌套于区域 tick 时，由外层区域控制 `tickInterval`、`duration`、`radius`；内层只提供伤害与自己的 `chance`。
- `summon` 的 `count`、`duration` 只用于非装备态；`placement`、`distanceFromTurret`、`replacesEarlier` 只用于装备态；`fireInterval` 对不开火的 `decoy` 固定为 0。
- `execute` 被动态只需要 `hpThresholdRatio`；`radius` 只属于触发式目标选择。

这些裁剪都有运行时分支，不属于“完全未消费”，但编辑器/手册应持续明确其上下文，避免玩家把参数理解为所有路径都生效。

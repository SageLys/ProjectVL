## 1. 通用交互定义（两方案共享）

竖屏三段式布局：HUD 条 / 主画面（释放区）/ 底部 dock（拇指热区）。装备区从画面左侧绝对定位移入底部 dock，跨屏拖拽消灭。

| 动词 | 语境 | 结果 |
|------|------|------|
| 单击主画面 | 命中掉落拾取半径内 | 拾取最近掉落 |
| 单击主画面 | 命中精英 bounty | 接单（集火+狂暴） |
| 拖卡 → 主画面抬指 | 任意星级手牌卡 | 消耗释放，落点=抬指点换算的画布坐标 |
| 拖卡 → 卡格 | 手牌内 | 移动/交换（触发自动合成） |
| 单击卡面 / 拖卡→装备格 | 视方案 A/B | 装备操作（见线框） |

判定规则：
- **点击 vs 拖拽**：pointerdown 后位移 < 8px 且 < 250ms 判点击，否则进入拖拽。此阈值是方案B「单击锁定」和主画面「点击拾取」都不误触发的前提，T1 实测校准。
- **手指遮挡**：拖拽中落点预览环偏移显示在手指上方 Δy（初始值 60px，T1 校准）。实际落点 = 预览环圆心，非手指位置。预览环半径读 `skills-schema` 的效果原子 AoE 参数；无落点语义的卡（纯 buff 压缩版）显示全屏微光而非预览环。
- **释放取消**：拖回 dock 区域抬指 = 取消，卡回原格。拖出屏幕/被打断（pointercancel）同取消。
- **PC 适配**：同一套 pointer 事件天然覆盖鼠标；快捷键（数字键 1–7 选卡+点击释放）进 P6 输入适配层，本次不做。

## 2. 方案A：独立装备格（默认方案）

见 `wireframes/交互线框_方案A_独立装备格.svg`。

- dock 两行：装备 3 格（上，紫框大格）+ 手牌 7 格（下）。装备/手牌拖拽路径 ≤ 90px。
- 装备动词：拖入装备格，或双击快速装备（触屏双击不可靠，可换长按，T1 定）。
- 门槛 ≥2★（现代码硬编码 3★，须改为配置 `equipMinStar`）；同类型唯一，拖入同型 = 喂养合成。

## 3. 方案B：锁定即装备（候选方案）

见 `wireframes/交互线框_方案B_锁定即装备.svg`。

- 共享池 10 格（2×5），无独立装备区。单击 ≥2★ 卡 = 锁定（=装备生效，上限 3），再击解锁。
- 锁定卡视觉三重冗余：金框 + 🔒 角标 + 底色。锁定卡不参与自动合成、不可直接拖拽消耗（先解锁，防误耗装备）；同型卡拖到锁定卡上 = 喂养合成。
- 主画面交互与方案A 完全一致——A/B 只隔离「装备操作」单一变量。

## 4. A/B 测试判据（纳入 P4 槽位压力建模 + T3 玩测）

| 指标 | 采集 | 判读 |
|------|------|------|
| 装备操作耗时（首次触达→生效） | 遥测埋点 | B 应显著更短，否则 B 无存在理由 |
| 装备操作误触率（误锁/误耗/误拖） | 遥测 + T3 观察 | B 的单击复用风险点 |
| 掉落过期率（KPI ≤20%） | 已有埋点 | B 满池捡不了新卡 → 过期率恶化则 B 出局 |
| 「锁定=装备」首局无指导理解率 | T3（对照 H3） | 低于半数则 B 需教学成本，倾向 A |
| 槽位满导致的合成停滞次数 | 仿真（P4 bot 扫 10格锁3 vs 7+3） | 验证 P4前置「~10格等效」在真人行为下是否成立 |

## 6. 实施顺序与前置

1. **T1 触控验证先行**（实证测试计划的唯一前置例外）：拿现原型手机实测 → 回填 `input` 配置三个值 + 决定双击/长按 → 才动 #4。
2. 清理层（#1/2/3/6/8，删 temp）可先行，与 T1 并行。
3. #4 pointerRouter → #11 接线 → #9/#10 布局 → #12 variant → #14 测试补齐。
4. 落点效果的真实结算依赖 P3 效果解释器；解释器就位前 `consumeCard` 用占位语义（等价旧临时栏加成+落点事件），保证本次改造可独立验收。

# 配置编辑器 v1 手动验收

## 0. 准备

1. 确认工作区没有需要保留但尚未记录的配置改动：`git status --short src/config/base src/data/texts.json`。
2. 启动开发服务器：`npm run dev`。
3. 打开终端输出的本地地址并访问 `/editor.html`。编辑器必须显示 15 个可写域；直接打开生产 `dist/` 时不应存在该入口。

编辑器的保存按钮只有在配置管线实时校验无 error 时才可用。warning 会显示但不拦截。每次保存成功后，若要在游戏中观察结果，需要刷新游戏页面。

## 1. 修改链锁闪电 bounces

1. 进入“技能”，在卡片搜索框输入 `chainLightning`，选择该卡。
2. 展开目标星级的装备态绑定，找到 atom 为 `chain` 的效果。
3. 将 `bounces` 改为与当前值不同的合法整数，等待右侧显示“可保存”。
4. 点击“保存 2 个域”（技能模块的结构与实体文案始终组成同一原子批次）。
5. 执行 `git diff -- src/config/base/skills.json`。

通过标准：

- 请求先经过 `/__config/validate`，再经过 `/__config/write`；
- diff 只包含目标 `bounces` 的值变化，不出现整文件重排；
- 未改动的 `texts.json` 即使参与双域批次也不产生 diff；
- 页面提示“刷新游戏页面后生效”。

记录原值后，将 `bounces` 改回并再次保存，避免把验收值留在配置中。

## 2. 悬空神池卡引用被拦截

1. 进入“神池”，点击“查看结构树”，展开 `gods[0].anchorCardIds`。
2. 引用字段默认使用卡 id 下拉。为验证服务端最终防线，可临时用浏览器开发者工具把该下拉当前 option 的值改成 `missing_editor_contract_card`，再触发 `change`。
3. 等待实时校验。

通过标准：

- 右侧出现 error，路径精确指向 `$.gods.gods[0]` 或更深的 `anchorCardIds`；
- 点击路径后，编辑区滚动并高亮对应字段；
- 保存按钮禁用；若在校验与点击之间制造竞态，`/__config/write` 仍返回 422 且文件不变；
- `git diff -- src/config/base/gods.json` 无新增差异。

重新进入“神池”或刷新编辑器即可丢弃该项未保存的非法内存值。

## 3. 编辑遗物名称并联动 texts

1. 进入“遗物”，选择任一条目并记下当前名称。
2. 在“名称与描述 · 写入 texts 域”中修改名称。
3. 等待 `relics` 与 `texts` 校验通过，点击“保存 2 个域”。编辑器会先分别预检两域，再分别经写回端点提交。
4. 执行 `git diff -- src/data/texts.json`，再执行 `npm run validate`。

通过标准：

- diff 只更新 `texts.relics.<id>.name`；
- `src/config/base/relics.json` 在只改名称时无差异；
- `npm run validate` 输出 0 error。

将名称恢复为原值并保存，最后再次确认配置目录没有遗留的验收差异。

## 4. 卡牌文案内联与双域原子保存（S3-工具3）

1. 进入“技能”，搜索并选择 `chainLightning`。
2. 在“名称与文案 · 写入 texts 域”修改“名称”，等待 `skills` 与 `texts` 都校验通过，点击“保存 2 个域”。
3. 执行 `git diff -- src/config/base/skills.json src/data/texts.json`。

通过标准：

- diff 只包含 `texts.cards.chainLightning.name` 的值变化，`skills.json` 无差异；
- `hand.shortByTier`、`hand.milestones`、`equip.shortByTier`、`equip.milestones`、`overview` 均按 `texts.json` 的现有结构出现，没有编辑器自造字段；
- 两域先分别请求 `/__config/validate`，全部通过后才请求 `/__config/write`。

继续制造整体失败：同时把卡片结构中的 `id` 临时改成会破坏引用的值，并保留一处未保存文案改动。实时校验应报精确路径、保存按钮禁用，两个文件均不落盘；即使绕过按钮直接提交非法候选，写端点也应返回 422。刷新页面丢弃非法候选，并恢复名称原值。

## 5. 神祇文案内联与双域原子保存（S3-工具3）

1. 进入“神池”，选择 `storm`，在内联文案区修改 `name` 或 `theme`。
2. 保存后执行 `git diff -- src/config/base/gods.json src/data/texts.json`。

通过标准：

- 只改文案时 diff 只包含 `texts.gods.storm.name` 或 `.theme`，`gods.json` 无差异；
- 若切到“查看结构树”，按第 2 节方法把 `anchorCardIds` 改成悬空引用并同时改文案，任一域预检失败时零次调用 `/__config/write`，两域均不落盘；
- 合法的神祇结构与文案修改会作为同一双域批次保存。

恢复验收值后重新加载页面。

## 6. 独立文案模块只保留全局段（S3-工具3）

1. 进入“文案”。
2. 确认页面提示 `cards / gods / relics` 已移至对应实体模块，且三段不再显示可编辑树。
3. 修改任一全局 UI 文案（例如 `buttons` 下的一项），保存后检查 `src/data/texts.json`。

通过标准：全局文案仍可正常编辑并只写 `texts` 域；实体文案不存在第二个编辑入口。恢复验收值。

## 7. 中文标签与解释覆盖（S3-工具1）

标签层是 `src/editor/labels.ts` 一处来源：原子中文名取 `texts.effectText.atoms`、原子解释取 `texts.glossary`、
参数解释优先取 `ATOM_CONTRACT[...].note`；参数名 / 域字段名 / 枚举取值这类开发者词汇补在标签模块内，不进 `texts`。
`tests/editorLabels.test.ts` 守住覆盖度与「不 import 配置管线」的浏览器安全边界。

### 7.1 随机挑 3 个原子确认参数中文

1. 进入“技能”，任选一张卡展开装备态绑定。
2. 把效果的原子下拉分别切到 3 个原子（例如 `chain` / `summon` / `statBuff`），下拉项本身应显示「连锁（chain）」这类中英并列。
3. 每次切换后检查参数区。

通过标准：

- 每个参数标题都是「中文名（englishKey）」，没有裸英文参数名；
- 原子标题下出现该原子的一句话解释（来自 `texts.glossary`）；
- 参数下方的灰色副标题优先显示契约 `note`；契约没写 note 的参数（如 `chain.searchRange`）也有解释，不留空；
- 枚举参数（`summon.kind`、`groundZone.shape`、`statBuff.stat`）的下拉项是中文，取值本身不变。

切换原子会清空 `params`，验收后请离开该卡或刷新编辑器丢弃未保存改动，不要保存。

### 7.2 挑 2 个非 skills 域确认字段中文

1. 进入“战斗”（`combat`），确认结构树顶层 15 个字段全部显示中文（画布 / 炮台 / 生命 / 基础数值 …），
   英文 key 作为灰色副标题并列显示。
2. 进入“经济”（`economy`），确认顶层 18 个字段同样全部中文。
3. 展开任意深层节点，确认未登记的字段名（如 `muzzleOffset`）**只显示英文 key**：回退，不报错、不阻断编辑。
4. 进入“遗物”，确认列表与详情显示遗物中文名，`axis` 下拉显示词条属性中文；进入“调参”，确认仍是原有中文标签。

通过标准：右侧校验面板无新增 issue，浏览器控制台无报错。

## 8. 交付门槛

依次执行：

```text
npm run validate
npm run test
npm run build
```

三条命令都应成功；`dist/` 中不得出现 `editor.html`、`editor-*.js` 或 `src/editor` 相关产物。

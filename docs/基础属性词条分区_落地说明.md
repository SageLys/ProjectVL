# 基础属性词条分区落地说明

## 边界

- `waveRewards` 独占 `damageAdd / fireRateAdd / rangeAdd / multiAdd / maxHpAdd / heal`，写入永久局内基数。
- 卡牌 `affixPool` 的基础属性出口仅为 `damageMul / fireRateMul / rangeMul / maxHpMul`。
- 11 个 `BuildScalingAxis` 只缩放卡牌机制原子或承载限时构筑奖励，不承载基础属性倍率。
- 词条是“每局每卡型一份共享模板”。合成、喂养和配方进化不会重掷或覆盖模板。

## 49 条候选迁移

| 旧词条 | 条数 | 新词条 | 新值域 |
|---|---:|---|---|
| `damageAdd` | 12 | `damageMul` | `0.04..0.12 step 0.04`（3 桶） |
| `damageAdd` | 12 | `damageMul` | `0.04..0.08 step 0.04`（2 桶） |
| `fireRateAdd` | 12 | `fireRateMul` | `0.02..0.05 step 0.01`（4 桶） |
| `maxHpAdd` | 13 | `maxHpMul` | `0.05..0.15 step 0.05`（3 桶） |

基线数据中一半 `damageAdd` 候选实际为 `1..2 step 1`，因此迁移为
`0.04..0.08`，不能统一扩成三桶。所有候选的数组位置、weight、
`consumableDuration` 与桶数均逐条保持不变。

倍率会持续放大后续 wave 平加，所以中后期必然强于只按参考时点做的静态等价换算。
这是 wave 扩大基数、卡牌放大基数的预期协同；强度标定应在固定 seed 对照后另开改动。

同一 bot、默认战斗数值、每帧保活，仅用于观察构筑与属性；决策均取第一项。

## RNG 回查结论

候选级检查逐索引通过：候选数组长度与顺序、weight、`consumableDuration`、桶数均未变化。
五个黄金 fixture 中，前三个切片与失败局的敌人生成哈希保持一致。通关局第一次分叉为：

- 帧 1250：新倍率使同一个 `ashHarvest` 掉落提前 4 帧产生；
- 掉落路径提前消耗共享 RNG；
- 帧 1254、敌人 id 54：旧版生成 normal，新版生成 tank。

因此该漂移不是 affix 抽取调用数变化，而是战斗数值改变后，击杀/掉落与敌人生成共用
单一 RNG 流所导致的动态交错。若要求任意数值变化后敌人生成仍零漂移，需要把生成、
掉落、卡牌等拆成独立 RNG 流；这超出本次只做词条分区的范围。黄金摘要现已记录
`enemySequence`，以后重录会保留可审计的生成证据。

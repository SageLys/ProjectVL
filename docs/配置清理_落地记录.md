## 1. 统一调参元数据

**迁移前三处来源**：`base/tuner.json`（min/max/step）、`ui/tunerSchema.ts`（label/group/waveDeferred 的 5 张手写表）、`ui/tunerPanel.ts`（3 个专用控件的内联 HTML + `GROUPS` 分组标题）。

**迁移后**：唯一来源 = `base/tuner.json` 的 `TunerParamMeta[]`（类型见 `config/types.ts`）。

| 角色 | 文件 |
|---|---|
| 数据（唯一来源） | `src/config/base/tuner.json` |
| 类型 | `src/config/types.ts`：`TunerParamMeta` / `TunerGroup` / `TunerParamType` |
| 读取 + 校验 | `src/config/tunerMeta.ts`：切片、路径存取、`validateTunerConfig` |
| 面板取数视图 | `src/ui/tunerSchema.ts`：切片 + `labelKey` → 文案解析 |
| 渲染 | `src/ui/tunerPanel.ts`：滑杆由元数据生成，专用控件按 `type`/`options` 分派 |

**逐字对照结果（迁移前 git HEAD vs 迁移后）**：

- 滑杆 **160 个**：路径、顺序、标签、min/max/step、分组、生效策略**逐一相等**，差异 0。
- 分组构成不变：waves 37 / combat 9 / enemies 29 / drops 33 / progression 2 / bounty 42 / p2 8。
- 浏览器实测（dev server）：面板共渲染 **163 个控件** = 160 滑杆 + 3 专用控件；分组标题、控件顺序、范围与迁移前一致，控制台无报错。
- 遗留 **13 项**（`combat.controlCeiling.*`、`combat.controlBudget.*`、`enemies.types.*.{knockbackResist,ccResist}`）：迁移前只有范围、没有标签、面板不暴露。现以 `exposed: false` 保留在元数据中并补齐标签，**仍不进面板**；要暴露时删掉该字段即可。

**新增能力**：
- `validateTunerConfig` 在配置加载阶段就校验路径唯一、指向真实数值、范围合法、枚举有候选。迁移前这些错误要等到面板渲染时才以 `tuner.json 缺少范围` 抛出。
- 专用控件（出怪模式 / 波末 Boss 波次 / Bounty 机制启用）进入同一张表，形态由 `type`/`options` 表达；其 pending/deferred 副作用仍由面板各自的事件处理器承担（**这部分逻辑本次未动**，见 §5）。
- `unit` 字段已在类型中预留，当前一律缺省，留给数值标定阶段填写。

## 2. 统一遗物文案

- `relics.json` 删除全部内联 `title`/`desc`（22 条），只留 `textKey`。
- 文本原样迁入 `texts.json` 的 `relics.<id>.{name,desc}`，**逐字一致（22/22 核对通过）**。
- 新增 `src/ui/relicMeta.ts` 作为遗物文案唯一入口（`relicCopy` / `relicCopyById` / `relicDisplayName`）；缺文案时回退到 id，不显示空白。
- `godValidator` 改为强制 `textKey === relics.<id>`，并**主动拒绝**残留的 `title`/`desc` 字段。
- 浏览器实测：`relicCopyById` 对随机抽查的 3 条遗物返回的名称/描述与迁移前内联文本逐字相同。

**顺带修正的一处分层问题**：`relicSelected` 事件此前携带 `title: string`（core 产出玩家可见文本）。文案迁走后 core 无从取得该字符串，事件改为只带 `relicId`，由 `ui/eventText` 依 `textKey` 解析显示名。这让「core 不依赖 texts」的分层重新成立；`devTelemetry` 本就不读 `title`，不受影响。

## 3. 融合词条预留（D2：只预留，不实现）

- 类型：`config/types.ts` 的 `CardFusionPolicyDef`，挂在 `CardDef.fusionPolicy`（可选）。
- 字段：`affixTransferPolicy`（none/strongest/sum/average）、`conflictResolution`（keepHigher/keepNewer/reject）、`sourceCardIds`。
- 校验：`skillValidator` 只做「声明了就得合法」——未知字段、非法枚举值、非字符串数组都会报错；**字段本身可选，缺省合法**。
- 运行时：**零消费者**。解释器、词条系统、loader 一律忽略。测试 `tests/skillsV04.test.ts` 断言：①现有 36 张卡一张都没声明；②声明后绑定解析结果与缺省完全一致。
- 文档：`docs/skills-schema.json` 新增 `definitions/fusionPolicy`，注明「实现见 Stage 5」。

## 4. 文案键完整性

新增 `tests/textsCompleteness.test.ts`（5 用例），与既有 `textCoverage.test.ts`（查内容质量）分工——这里查**引用对不对得上**：

- 每条遗物的 `${textKey}.name` / `.desc` 命中且非空；配置层不得再出现 `title`/`desc`。
- 每个调参 `labelKey`（176 条，含保留项）与 7 个分组标题命中。
- 卡牌 / 进化分支 / 神的 `textKey` 都能解析到文案节点。
- **无孤儿**：`texts.relics` 与 `texts.tuner.params` 的条目数与配置引用数严格相等，多写的文案会被判失败。

配套新增 `src/data/index.ts` 的 `resolveTextNode` / `resolveText`：按 `.` 逐段下钻，且每层允许「剩余整串」作为字面键命中——这样 `relics.proj_damage.name`（嵌套）与 `tuner.params.combat.defaults.damage`（键名含 `.` 的扁平表）走同一个解析器。

## 2. 项目背景与最初目标

**项目定位**：Vite + TypeScript 可玩原型，最终目标是产出**可直接 Unity 复刻的完整核心逻辑**（不做美术）。`core` 层为纯规则 + 注入 RNG + GameEvent，必须保持。

**从哪里开始**：2026-07-03 的立项案 docx，加上 `01-立项模板` 到 `10-全量打包` 十期单文件 HTML 迭代。07-07 判定"原型继续长下去无法安全迭代"，用 6 步小步提交、逐条行为契约锁死行为一致，重构为模块化工程。

**最初的三条核心决策**（07-08，【用户明确提出】【项目记忆】）：

1. **全自动炮台**——玩家只管卡牌，不管瞄准与射击
2. **"有限行动次数"机制彻底砍掉**
3. **单局结构 = 固定波次 + Boss**（无尽仅作数值验证）

这三条至今未被推翻。它们共同表达一件事：**把有限的操作预算全部让给卡牌决策。**

> ⚠ **证据空白**：立项案 docx 与十期 task-records 本轮未读，用户最原始的设计意图仍缺。

## 5. 关键设计问题的演化

### 5.1 "什么是可检验的目标"

```
07-09  "没有 KPI 就没有靶子"，定三项局级 KPI
  ↓
07-12  发现 KPI 选错了层级：全是局级聚合，波8的29只敌人把波1的空屏平均掉了
       → "玩家的体验不发生在'局'这个粒度上，发生在每一秒"
  ↓
07-12  E1–E7 秒级体系 + "前90秒"独立切片门
  ↓
07-14  R1-B 只锁定感知/威胁层（E1/E4/E5/E7）；E2/E3/E6 显式推迟
  ↓
07-23  8→10 波，KPI v2 定版文件被清空
  ↓
至今   度量层实装并沿用（metrics.ts + 46份遥测），门槛定版中断，E2/E3/E6 从未回填
```

**准确表述**：**指标定义与自动测量已落地并沿用至今，门槛值定版中断。**

### 5.2 "数据和人谁说了算"

```
07-10  4000局仿真定星级上限/合成方式
  ↓
07-10  【用户质疑后复审】把结论分成序数/不敏感性/默认值/设计锚四级
       写下："抽象仿真只能提前定两类结论，绝对标定必须等实测"
  ↓
07-12  27300局仿真被90秒真人试玩推翻——上面那句话自己写过，执行时没照做
  ↓
07-14  主动把教训用在新场景："抽象 merge_sim 在真卡实装前无意义、会重蹈 P4 仿真先行错"
  ↓
08-04  同一逻辑用在 AI 报告上：4处硬错3处半真，最强证据被判成最弱
```

**这条线的形状**：**写下方法论 → 违反方法论 → 内化方法论 → 迁移到新领域。**

### 5.3 "内容怎么才能不同质"

```
07-10  "废除纯数值加成卡"——在【卡的效果】层
  ↓
07-23  "神必须像 Hades 的神，而非功能类别"——在【身份包装】层
  ↓
07-29  "缺的不是更多原子，是卡与卡之间可交易的资源"——在【资源交换结构】层
       （41卡全是自闭环：触发→立即结算→结束）
  ↓
07-30  "引擎根本没有目标定位层"，64/210支字节级同构——在【引擎原语】层
  ↓
07-30  "设计表是散文、校验器没有设计期望的机器表示"——在【契约与校验】层
```

**这条线一路下沉了五层**，每一层都比上一层更根本。最后落到的位置（把设计表编译成机器可读期望 + 硬失败校验）已经不是内容问题，是**内容生产的基础设施问题**。

### 5.4 "注意力预算"

```
07-09  波内1–3次决策/分钟（锚：Gossip Harbor / Travel Town 合并类游戏）
  ↓
07-12  发现锚错品类："手上轻、脑子重"被实现成了"手上轻、屏幕空"
  ↓
07-14  拆成两层：
       层一 认知决策层 1–3次/分（拾取点击、观察、走位不计入）
       层二 感知/威胁层（新锚 VS/Brotato 首分钟：手可以闲，眼睛永远忙）
```

**一句话**：**决策可以稀疏，刺激不能稀疏。**

### 8.1 最值得讲的三条否定

1. **否决了 ChatGPT 的"对 11 张按 5:3:3 加权"**——因为它会与已有的 `build.topK=3` 打架。正确接法是把神的影响**分派到 discovery/pivot**，让 build 继续锁在正在炖的 3 条链上。**这是"新系统不与旧系统争夺同一决策"的示范。**

2. **否决了自己的"铸/耗对立"分叉法则**——因为 `interpreter.ts` 的绑定是**累加**的，互斥角色不能累加。**职责划分由引擎事实决定，不由美感决定。**

### 9.2 时间线的可信度分层

1. **Git 提交时间**——最可信，已由 `docs/Git版本迭代报告` 整理
2. **文档内写明的日期**——次可信，本报告统一采用

4. **文件 mtime**——**不可信**，挂载/复制/分支切换都会改写

### 9.3 三处 Git 与任务记录无法对应

- **07-18～07-20、07-25 无提交**：Git 报告称"可理解为设计沉淀窗口"，**这是推测**，本轮无法确认

- **`docs/P4前置_星级合成与卡槽_结论.md` 等已删文档**：记忆多次引用，原文不可考

### 9.4 一条重要的方法论纪律

**Git 只能证明修改发生，不能倒推设计意图。** 本报告全程遵守：凡是只有 commit 没有决策记录的（如密度改分段曲线、装备语义推翻），一律标注"只有实现没有设计说明"，**不用最终代码去反推"我一开始就想好了"。**

## 10. 我的设计思维特征

完整分析见 `07_DESIGN_THINKING_ASSESSMENT.md`。此处只列结论与对应实例：

### 10.1 五项优势（每项都有 3 个以上实例）

| 特征 | 最强实例 |
|---|---|
| **把主观感受翻译成可推演的量** | "游戏很无聊" → 波 1 逐项推演表六行，与主观描述逐项吻合，据此定性为数值问题而非手感问题 |
| **把抽象体验诉求钉在具体字段上** | "像 Hades 的神" → 新增独立 `god` 字段，旧 `BuildTag` 降级为机制标签 |
| **比较维度选得比方案本身准** | 入装门槛在经济上无差异 → **明确宣布数据无效，改按体验定** |
| **约束意识（尤其是引擎约束）** | 同一天内被 `interpreter.ts` 累加语义与 `equipSlots=3` 各推翻一次方案，两次都立即改设计 |
| **默认不信任 AI 输出，逐条核代码** | 08-04 核出 4 硬错 3 半真，其中 46 份真人遥测被误判为"空文件"——最强证据被判成最弱 |

### 10.2 四个盲点（同样有证据）

| 盲点 | 证据 |
|---|---|
| **度量闭环断在最后一公里** | KPI 定版被清空未重写、E2/E3/E6 从未回填、S4b 从未执行、A/B 五项判据从未测 |
| **推翻自己时不记录动机** | 装备语义推翻、密度改分段曲线，都只有结果没有理由 |
| **对"减少玩家选择"缺少论证** | 奖励蓄力条"全程不做选择"与定位"脑子重"的关系**从未被讨论** |
| **已知问题清单只增不减** | E2 超标 3 倍、E7 全波不达标、过期率 88.2%、42 处 `onKill` 打空……全是自己发现并写下来的 |

**关于第四点要公平地说**：这份清单之所以存在，恰恰是因为项目建立了能发现它们的工具。**没有工具的项目不是没有这些问题，是不知道自己有。**

### 10.3 成长轨迹

**相信计划 → 被现实打脸 → 相信人在环路 → 发现执行会偏离设计 → 相信机器可读契约 → 发现叙述也会偏离事实 → 相信可复现命令。**

每一环都是"信任的对象往下沉一层"，且**每一环都有具体产物可以指认**（调参环工具链 / designFingerprints.json / 事实核查报告）。

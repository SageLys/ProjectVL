# 设计思维特征分析

> 规则：每一项判断必须附具体案例；不写"很有能力""思维缜密"这类无信息量的话；盲点与优点同等篇幅。
> 归属限制统一说明：本文件的判断依据中，**约 40% 来自能直接读到的用户原话或用户执笔/确认的文档，60% 来自项目记忆的转述**。凡只有转述支撑的，行文中已注明。

## 一、问题定义方式：先把主观感受翻译成可推演的量

这是本项目最稳定的一个特征，出现了至少四次。

### 实例 1（最强）·"游戏很无聊" → 波 1 逐项推演表

07-12 试玩后没有停在"不好玩"这个判断上，而是要求按当时配置**逐项推演**：8 只敌人 / 5.12s 出怪 / TTK 0.85s / 射程 430 / 同屏 0–1 只 / 全波 2 次操作。推演结果与主观描述**逐项吻合**，于是得出一个很硬的定性：

> "无需归因于'手感'或实现 bug——这是数值设计本身的直接后果。"

**这一步的价值**：它把"我觉得不好玩"从一个不可辩驳的主观陈述，变成了一个**可以被检查、可以被反驳、可以被修复**的技术命题。

### 实例 2 ·"每局玩起来都一样" → 并行合成链 ≈ 3

07-23 面对"构筑广度不足"，没有停在"卡不够多"，而是找出了**约束这件事的那个数**——并且发现它已经在代码里被写死了三次（装备槽 3 / 手牌 7 槽 + 二合 / `build.topK=3`）。

**关键动作**：不是发明一个新数字，而是**找出已经存在的那个数字**。由此"一主二副"从拍脑袋变成了被 3 个装备槽反推的结果。

### 实例 3 ·"五个神玩起来差不多" → 五组硬数据 + 一个结构性论断

07-29 的 41 卡体检给出：33 原子中 9 个全 5 神共用、仅 2 个独占；3★ 指纹撞车 3 处；9 个纯数值占位分叉；闸门覆盖率 39% 且偏科；主类别分布死板的 (3,1,1,1,1)。

然后是论断：**"缺的不是更多原子，是卡与卡之间可交易的资源。"** 41 张卡全是自闭环（触发→立即结算→结束），所以卡间只能做加法。

**这一步比数据更值钱**：数据说明"确实同质"，论断说明"为什么必然同质"。

### 实例 4 ·"卡还是一样" → 64/210 支字节级同构

07-30 把"分支差异不够"量化到**字节级完全相同**这个精度，并给出 27 组的具体清单。

### 小结

四次的共同模式：**主观现象 → 找出可测量的代理指标 → 量化 → 从量化结果里读出结构性原因**。第四步（读出结构性原因）是区分"会做数据"和"会做设计"的地方。

## 二、体验拆解方式：能把抽象体验诉求钉在具体字段上

### 实例 1 ·"张力峰值放在每波末与 Boss 前，波间是呼吸口"

07-09 的原始需求里就出现了这句【用户明确提出，原话可引】。它同时给出了**体验形状**（峰值位置 + 呼吸口）和**可测量形式**（后来的 E7 波尾冲刺 ≥1.5×）。

### 实例 2 ·"像 Hades 的神，而非现在的功能类别"

07-23【用户明确提出，记忆转述】。"身份感"是最难落地的体验诉求之一，处理方式是：新增独立 `god` 字段，旧 `BuildTag` **降级**为机制标签只供遗物缩放。

**注意"降级"这个动作**：不是并存两套标签，而是明确谁是身份、谁是机制。这避免了标签体系膨胀。

### 实例 3 · 五神资源类型区分的是"决策结构"而非"效果"

07-29 最终方案：迅霆=并发型 / 凛冬=阈值型 / 焚狱=条件型 / 磐垒=存量型 / 丰饶=流量型。

参照 Hades 的观察：**"差异化活在'兑现条件'而非'效果'"**（Jolted/Doom/Hangover 效果都是延迟伤害）。所以身份下沉到 trigger + 闸门层。

**这是本项目体验拆解的最高水位**——它区分的不是玩家看到什么，而是**玩家的决策结构**。

### 实例 4 · 注意力预算两层化

"决策可以稀疏，刺激不能稀疏"——把一个原本混在一起的预算拆成认知决策层（1–3 次/分）与感知威胁层（每 3–5 秒一个事件、同屏常驻 4–10 敌），并明确"拾取点击与观察事件不计入认知层"。

### 反例：有一处体验诉求之间的张力从未被讨论

- 07-10 定位：**"手上轻、脑子重"**
- 07-30 奖励蓄力条：**"玩家全程不做选择"**，体验目标是"简化 + 更直接的正反馈"

这两者的关系在现有全部记录里**没有出现过一次讨论**。可能是有意的（把"脑子重"收敛到卡牌构筑层，把波末奖励层做轻），也可能是没意识到。**目前无法判断，属于【来源不明】。**

## 三、方案比较方式：比较维度选得比方案本身更关键

### 特征：几乎每次比较都会先问"判据是什么"

| 决策 | 比较维度 | 为什么这个维度是对的 |
|---|---|---|
| 3★ vs 4★ 上限 | **首件到手时机**（@31 拾取太迟） | 星级上限的意义是玩家能不能用上，不是数值空间多大 |
| 二合 vs 三合 | **是否击穿注意力 KPI**（8.8 次/局 vs ≥16） | 合成频次是注意力开销 |
| 入装门槛 1/2/3★ | 经济上无差异 → **按体验定** | 承认这个维度上数据给不出答案 |
| 方案A vs 方案B | 5 项判据（操作耗时/误触率/过期率/首局理解率/合成停滞） | 覆盖操作、认知、经济三层 |
| 单波5-7卡 vs 并行链≈3 | **锚点是否已被代码写死** | 写死的约束比设计意图更硬 |
| 15条 vs 25格配方 | **零配方局概率 + 卡牌闲置数 + 是否需要运行时补救** | 第三项是决定性的 |
| 补窟窿 vs 设计指纹夹具 | **能否防复发** | 唯一真正的判据 |
| 多难度改 B+C vs 只改 C | **是否护住手感基线** | 已调出的手感是资产 |

**最能说明问题的是"入装门槛"那一行**：数据显示 1★/2★/3★ 在经济上没有差异，于是**明确宣布这个维度上数据无效，改按体验定**。承认数据回答不了的问题，比强行用数据回答更难。

### 特征：会主动为 A/B 实验保持单变量

07-10 的方案A/B 线框，"两方案主画面交互完全一致以隔离 A/B 单一变量"。这是实验设计意识，不是设计意识。

### 弱点：A/B 判据定了但从未执行

方案 A/B 的 5 项判据从未实际测过——07-12 用**语义冲突**（锁定可逆 vs 装备永久）直接废弃了方案 B。

**这不算错**（语义冲突确实不需要 A/B 测），但意味着**"定判据"和"跑实验"之间有一道没跨过去的坎**。这在 E2/E3/E6 回填、P4.1 防过载重跑、S4b 上重复出现（见 §六）。

## 四、竞品使用方式：从"抄数字"到"检查锚是否同构"

这条有清晰的成长轨迹，是本项目最好的一条成长线。

### 第一阶段（07-09）：把竞品当数值来源

用 Brotato（20 波 20–25 分钟）、VS（最短 15 分钟）、20 Minutes Till Dawn 校准单局时长；用 Gossip Harbor（4.5 分钟/会话）、Travel Town（4 分钟/会话）校准注意力预算。

做得好的地方：每条 KPI 强制要求"**竞品基准 + 来源日期 + 检验埋点方法**"三件套，并区分实测/估算/社区共识/推断四种置信级别防编造。

### 第二阶段（07-12）：发现锚错了品类

**注意力预算的锚（合并类游戏）与本作（实时射击场）不同构。**

> "那是无实时威胁、异步节奏的品类。而本作是实时射击场，正确的锚是 VS/Brotato 的感知负载——那些游戏第一分钟同屏就有 5～15 只敌人，玩家手可以闲，但眼睛永远是忙的。"

处理方式不是简单换锚，而是**作废旧锚 + 限定它的适用范围**："它只该继续为'认知决策层'提供参照，**不得约束'屏幕上发生的事件'**。"

### 第三阶段（07-23、07-29）：只借用结构，不借用数字

- 神池设计里 Hades 的用法是"**神的身份感**"这个结构概念，不是任何具体数值
- 五神差异化里 Hades 的用法是"**差异化活在兑现条件而非效果**"这个观察，并给出三个具体例证（Jolted/Doom/Hangover 都是延迟伤害）

### 小结

**07-09 抄数字 → 07-12 检查锚是否同构 → 07-23 只借结构。** 这三步是一条真实的能力成长，而且每一步都有具体产物可以指认。

## 五、约束意识：这是最突出的一项

### 类型 1：工程约束优先于设计美感

07-29 同一天内被代码事实推翻两次，两次都立即改设计而不是要求改引擎：

- `interpreter.ts` 绑定**累加** → "铸/耗对立"作废（**互斥角色不能累加**）
- `economy.json` 的 `equipSlots: 3` → "产销链 ≥2产≥2销"作废，设计单元改为**"一对卡"**

原则写得很直接：**"职责划分由引擎事实决定。"**

### 类型 2：主动核实"设计稿写过"与"引擎支持"的差别

07-30 之后写给自己的教训：

> **"给 Codex 的规格里不要把'设计稿用过'当成'引擎支持'——写复用清单前必须实际 grep 运行时代码。"**

同类的还有 07-23 发现"docx 里写的独立 Boss 100–120 秒**在代码里根本不存在**"。

### 类型 3：内容量成本被明确写进阶段计划

11 张 → ≈35 张，"**近 3 倍内容**。这是神池系统能扩大局间广度的**代价**，得进你的阶段计划。"

没有把成本藏起来，也没有含糊成"内容会增加"。

### 类型 4：知道哪些约束是硬的，哪些是可谈的

- 硬：`equipSlots=3`、`build.topK=3`、绑定累加、`onKill` 时敌人已 splice、`shield` 容量取最大
- 可谈：波数 8→10、装备语义、星级上限

区分方式：**能不能在配置里改** vs **要不要改引擎**。

### 类型 5：为 AI 协作预留边界（本项目特有）

- `core` 层禁止 DOM、禁止为单卡写 if
- 随机数一律经注入 `rng`（保证固定 seed 可重现）
- 新反馈一律走 `state.vfx`、**绝不新增 `spawnParticle`**（否则推进 rng 流、破坏回放确定性）
- `designFingerprints.json` **严禁从 `skills.json` 反向生成**

最后一条尤其值得注意：它防的是**校验器与被校验对象同源导致的自我验证失效**。

## 六、测试意识：定义能力强，闭环能力弱

这是本项目**最明显的一处不对称**，必须诚实写出。

### 强的一面

| 项 | 证据 |
|---|---|
| 会为主观体验定义可自动测量的指标 | E1–E7 全部实装在 `src/telemetry/metrics.ts`，`npm run metrics` 可跑，有回归测试 |
| 会设计"防空转下限"而不只是"防过载上限" | 07-12 四条方法论第 3 条 |
| 会做恒等变换回归对照 | 多难度 hell 档 = 全 1 倍率，阶段 1 先证"地狱恒等" |
| 会用固定 seed + 黄金回放守确定性 | `tests/golden/`、`tests/fusionOrderInvariance.test.ts` |
| 会用脚本做可复跑体检 | `scripts/audit_content.py` 六段输出 |
| 会用穷举验证结构性结论 | 25 格配方 7500 状态穷举 |
| 会在事故后加校验防复发 | `validateTextsFile` 接入构建流程 |
| 会自己核查 AI 生成的分析 | 08-04 发现 4 硬错 3 半真 |

### 弱的一面（同样有具体证据）

| 项 | 状态 |
|---|---|
| `docs/P6_新KPI体系_v2_定版.md` | **文件被清空，至今未重写** —— 有尺子，没有刻度 |
| E2 / E3 / E6 回填 | 07-14 显式丢弃，"待 S5 后实测回填"，**回填从未执行** |
| S4b（真卡遥测重写 merge_sim） | **从未执行**，S4a 的口径澄清悬空 |
| P4.1 防过载结论重跑 | 声明"全部作废待重跑"，**未见执行记录** |
| 方案 A/B 的 5 项判据 | 定了，**从未测过** |
| `p6-r1-start` tag / `P6_基线核对报告.md` | R1-0 验收标准要求，**从未创建** |
| 首局通关率 15–25% | 项目"最重"的假设，**从未被真人验证** |

**模式很清楚**：**定义标准的能力 ≫ 把标准闭环的能力。** 每次到"该回来填数字了"的那一步，项目就转向了下一个更有意思的系统。

**但也要公平地说**：这个模式有一部分是**主动权衡**的结果——07-14 拆 S4a/S4b 时明确说过"抽象 merge_sim 在真卡实装前无意义"，也就是说 S4b 的推迟是有理由的推迟。问题在于**推迟之后没有回来**。

### 一处矛盾（保留不消解）

E2 的地板是 ≤4s，当前实测逐波 3.93–11.98s，前 90 秒切片 6.60s——**空转问题从未被解决**。但 07-12 的整个反思恰恰是围绕"空转"展开的。

也就是说：**项目正确诊断了空转，重建了度量它的能力，然后把它掩盖在密度之下，而不是解决它。**（`docs/作品集证据核对报告` 的原话：**"空转问题没有被解决，只是被密度掩盖了。"**）

## 七、接受与反驳建议的方式

本项目有大量与 AI（Claude / ChatGPT / Codex）的协作记录，这一项证据特别充分。

### 特征 1：默认不信任，逐条核代码

| 时间 | 事件 |
|---|---|
| 07-23 | ChatGPT 的构筑方案 → 核出三件它没看到的事（全库只有11张 / 无独立Boss / 已有流派底座） |
| 07-24 | ChatGPT 的缺陷清单 → 真实缺陷 4 项，**不实项 2 项**（`heal` 根本没有卡带，只是潜在隐患） |
| 07-22 | BOSS 参考稿 → 方向对，但画布尺寸、hell 难度倍率、奖励发放点全错 |
| 07-29 | ChatGPT 报告 → 指出四个问题，含"它引用的 `mergeRule` 原子**已在 commit 277a380 退役**" |
| 08-04 | ChatGPT 作品集报告 → **4 处硬错 3 处半真**，最严重的一处把 46 份真人遥测（3MB）误判为"空文件" |

由此形成明文原则：**"AI 生成的分析进母档前必须人工用可复现命令核验。"**

### 特征 2：接受时会说清"接受的是哪一部分"

07-29 第三轮：ChatGPT 报告的"运行时断言逐条核实**全部成立**"——所以那一轮的技术事实被完整采纳，同时它的方案层建议仍被替换。**事实层与方案层分开评价。**

### 特征 3：自己的判断被证伪时也照样撤回

- 07-29 上午自己推的"铸/耗对立" → 被 `interpreter.ts` 累加语义推翻，当天作废
- 07-30 Claude 的 15 条方案 → 被用户的 25 格取代，Claude 在文档 §1.1 撤回三条主张

### 特征 4：对交付物可执行性的要求很直接

> "你写的计划太难看懂。"
> "请再说明清楚我自己调参的任务。"
> "用清楚移动的语言向我解释这些可调参数的意义。"

三次都不是要求改结论，而是要求**改成自己能执行的形式**。此后 68 份 `codex-prompt-*.md` 都按"可直接复制派发"的标准写。

## 八、思考盲点（四个，都附证据）

### 盲点 1 · 度量闭环断在最后一公里

见 §六。**这不是能力问题，是注意力分配问题**——每次到了"回填数字"这一步，就有一个更有意思的系统在等着。

**如果要改**：给每个"待回填"项设一个显式的到期日和阻塞关系，像 C1–C3 架构分水岭那样做成**硬门禁**，而不是写在文档角落。项目已经证明自己会遵守硬门禁。

### 盲点 2 · 推翻自己时不记录动机

装备语义从"永久不可撤销"改成"可撤销/可消耗"，**只有结果和日期，没有一个字的理由**。同类情况还有：密度从平铺 14 改成分段曲线，只有数据没有决策对话。

**代价是直接的**：这两条都是很好的作品集案例，但面试官问"为什么改"时，答案不在任何记录里。

**如果要改**：推翻自己时，在 commit message 或文档里多写一行"因为 X"。成本极低。

### 盲点 3 · 对"减少玩家选择"的设计后果缺少论证

奖励蓄力条把"升级三选一"改成"全程不做选择、自动执行、点一次确认"。理由记录只有"简化 + 更直接的正反馈"一句。

与 07-10 定位"脑子重"的关系**从未被讨论**。这可能完全没问题（构筑决策在卡牌层），但**没有被讨论**这件事本身是盲点——项目对其他每一个决策都会追问"这服务什么体验"。

### 盲点 4 · 已知问题清单增长快于关闭速度

当前明确记录在案但未处理的：E2 空窗超标 3 倍、E7 波尾冲刺 10 波无一达标、掉落过期率 88.2%（超 KPI 4 倍）、波 9/10 密度结构断裂、`retribution` 3★ 三支身份被抹除、42 处 `onKill` 打空、14 处 6★ 覆盖抹平分支、`requiresSource` 的 `retaliation` 永久不可达。

**这些都是自己发现并写下来的**——发现能力很强。但清单只增不减。

**⚠ 但要公平**：这份清单之所以存在，恰恰是因为项目建立了能发现它们的工具（`audit_content.py`、`metrics.ts`、`validateConfig`）。**没有工具的项目不是没有这些问题，是不知道自己有。**

## 九、成长轨迹（有明确的分界点）

## 0. 现状快照（读代码后的关键事实）

- 架构已达标的部分：`src/core` 纯规则层 + 注入式 RNG + GameEvent 事件流 + 每系统单测。这个骨架**正是 Unity 复刻需要的形态**，重构时必须保住。
- 炮台已是**全自动索敌+自动开火**（`combatSystem.findTarget` 锁最近敌人）。玩家的实际操作 = 点掉落 + 拖卡 + 三选一。这与立项案写的"拖动瞄准"已偏离，且这个偏离**从根本上改变了目标受众和竞品集**——现在更接近合成塔防/放置防守，而不是射击游戏。这必须先拍板（见 P0-1）。
- 立项案的核心支柱"**有限行动次数**"在代码里只剩统计计数（`state.uses`），没有任何限制。是砍是留是变形，没人决策过（见 P0-2）。
- 当前数值仅是占位：5 波、boss 在第 5 波、xp 曲线 8×1.35^n、starScale [1, 2.25, 4]。一局估计 3–5 分钟，距立项案 8–15 分钟目标差一倍以上。
- 卡牌 = 5 种纯数值加成，合成上限 3 星，3 星才能入装备栏（3 格），卡槽 7 格，临时栏任意星级、当波生效。

## 1. 对你四步计划的核心意见：顺序要改

你的顺序是 ①受众/时长 → ②数值计算 → ③配置重构 → ④技能体系。**建议改为 ① → ④框架 → ③ → ②/④内容并行**，理由：

1. **数值依赖技能体系**。你要废掉纯数值卡，那么"成长曲线与极限"就不再是一条 DPS 曲线，而是"功能组合的强度空间"。技能没定框架之前算的任何波次/曲线数值都会作废。
2. **配置架构依赖技能数据模型**。功能型技能的 JSON（触发器、效果原子、双模式、星级质变）比现在的平面加成复杂一个量级，配置组织方式必须围绕它设计，否则重构两遍。
3. **数值是最便宜、最后做的**。架构错了要重写，数值错了改 JSON。所以贵的先定，便宜的后调。
4. 受众/时长（①）确实该最先做，因为它决定注意力预算和单局结构——但它有一个前置：**P0-1 操作模式**不定，竞品集都选不出来。

## 2.1 交互重设计（P0-3 决策衍生，进入 P2 范围）

结论：不做子弹时间/暂停，靠交互本身降耗时。方向已定，具体方案待设计：

1. **消耗释放**：卡牌拖入整个上方主画面区域 = 一次性释放技能（取代拖入临时栏小方框）。临时栏 UI 可移除。
   - 顺带的设计机会：**释放点 = 技能落点**。功能型技能（AoE/冰冻/领域）因此天然获得空间瞄准维度，消耗品用法从"全屏一刀切"升级为有操作感的决策——建议 P2 设计技能时默认利用这一点。
2. **装备区重排**：装备格移到下方卡槽区旁，消灭跨屏拖拽。
3. **锁定即装备（待细化的候选方案）**：不设独立装备格，点选"锁定"卡槽内符合星级条件的卡即自动激活为装备（上限 N 张，锁定卡有明显视觉态）。
   - 优点：装备操作从"拖拽"降为"单击"；库存与装备合一，界面更干净。
   - 代价：锁定卡占用卡槽容量，槽位压力与装备数量耦合（7 槽锁 3 张后只剩 4 格周转）——这个耦合本身可能是好玩的取舍，也可能是挫败源，**需要与"独立装备格在卡槽旁"方案做 A/B**，并纳入 P4 的槽位压力建模。
4. 交付：交互线框图（两个装备方案各一版）+ 输入层改造清单。

### P2 技能体系框架（你的④，只做框架不做全部内容）
- **效果原子库**：弹道类（穿透/连锁/分裂/弹射/AoE）、控制类（减速/冰冻/击退/嘲讽）、领域类（光环/地面区域/持续 DoT）、经济类（掉率/经验/合成规则改变）、防御类（护盾/反伤/突破惩罚减免）。
- **触发器库**：onFire / onHit / onKill / onWaveStart / onBreach / onPickup / interval / onMerge。
- **星级质变模板**（解决"星级要有质的区分"）：1★=基础机制，2★=机制+修饰符，3★=形态变换。例：连锁闪电 1★命中弹跳 1 次 → 2★弹跳 3 次+减速 → 3★变成环绕炮台的雷暴领域。
- **一卡两用规则**：消耗品效果 = 同一幻想的"压缩即时版"。冰冻卡：装备=子弹附带减速；拖入战场=以落点为中心的大范围冻结 3 秒。写成硬规则，避免每张卡单独发明消耗逻辑。
- **规模控制（重要意见）**：首批 6–8 张，覆盖五个原子类别各至少 1 张，不要 15 张。功能型技能的设计/实现/测试面 = 张数 × 星级 × 2 种用法，膨胀极快。另建议保留 1–2 张"一眼看懂"的简单卡给前期教学，复杂度预算要留。
- **（2026-07-10 增）点击多功能化与主动风险选择**：技能/机制设计须服务「位置→注意力」映射——点击动词承担多种功能且互相争夺注意力；至少设计一种「主动选择面对哪股敌人」的机制（岔路波次/精英 bounty/险区掉落/诱饵，候选待筛）。
- 交付：`skills-schema.json`（数据模型）+ 首批卡牌设计表（含每星级、每用法的完整描述）。

## 4. 风险清单

1. **功能型技能的组合爆炸**：8 张卡×3 星×2 用法=48 个效果态，两两组合更多。对策：效果原子正交化 + 仿真 bot 扫描异常组合（无敌/零 DPS/软锁）。
2. **注意力冲突**（立项案已识别）：全自动炮台后缓解，但 3★ 领域型技能可能让画面信息过载，波间窗口的节奏要靠 P0-3 决策兜底。
3. **Unity 浮点/时序漂移**：靠统计验收而非逐位验收；判定顺序在规格书里写死。
4. **消耗品价值失衡**：消耗 3★ 卡=放弃一件永久装备，机会成本极高，压缩版效果必须"救场级"强度才有人用。这是 P4 要专门建模的一条。
5. **perk 三选一与卡牌构筑的定位重叠**：明确分层——perk=平滑保底成长（纯数值），卡牌=尖峰构筑决策（功能）。两条曲线在 P4 里分开建模再叠加。

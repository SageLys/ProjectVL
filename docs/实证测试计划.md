# 实证测试计划

日期：2026-07-10 ｜ 状态：已确认；T1 已逾期 ｜ 启动时点：T1 立即可做；T2/T3 在 P5 正式内容后

> 2026-07-12 更新：P4.1 已先按 provisional 参数实现统一输入、Bounty、共享注意力仿真与 localStorage 遥测。它不能替代 T1 真机或 T2/T3 真人验证；取得真机触达、误触和帧时间前，不得宣称触控体验/物理性能已标定。

背景：盲区评审（2026-07-10）的元结论——纸面决策速度远快于实证速度，推理链末端建在推断上的比例随链长升高。本计划列出成本最低的实证动作与待验证假设，防止把「地图」当「领土」。

## 测试动作

### T1 · 手机浏览器触控验证（逾期验收义务）

用手机浏览器直接跑现有原型，验证鼠标环境下不可见的问题：

- 帧率与敌潮规模上限（明确 P4 数值标定时的性能假设，防止网页性能天花板反向污染数值）
- 双手持机的点击体验：拇指可达区、误触率
- 手指遮挡 vs「释放点=落点」：拖卡释放时手指是否挡住落点
- 战斗中点掉落的最小目标尺寸
- 产出：触控适配约束清单 → 回填 `input.json` 的 8px/250ms/60px/44px，并校准 P4.1 三种画像

### T2 · 自玩数据复盘（P5 完成即做）

- 用 P4.1 遥测（localStorage，DEV API 导出/清空）跑若干真实局，对照 KPI：单局时长、合成、过期、呼吸、3s/10s 峰值、队列延迟、动作类型和 Bounty 路径
- 与 P4.1 fast/target/stressed 包络对比，用真人数据替换反应时、错误率和切换成本；这些画像不是预先存在的真人分群

### T3 · 目标画像玩测（P5 后，5 人起）

- 招募：25–35 岁、玩过合成塔防或轻度幸存者like、非硬核
- 观察首局全程（不指导）：卡死点、教学理解、限时窗口的情绪反应、是否开第二局
- 半结构化访谈 + 遥测数据配对
- 注意：施测者本人不是目标画像，自玩感受不能替代此环节

## 相关定案备忘（2026-07-10）

- 项目定位：个人作品集展示，暂不考虑商业发行；题材包装后期可换（KPI 表中商业指标按设计靶子理解，非商业承诺）

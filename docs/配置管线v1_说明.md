## 1. `npm run validate` 的校验清单

报告按 **base + 每个已注册 variant** 各跑一遍（避免"只在 base 下合法、切到 dev-short 就炸"）。

### schema 层（复用既有 fail-fast 校验器，逐域独立 try/catch）
| 检查 | 覆盖 |
|---|---|
| `schema:skills` | 卡牌结构 v0.4.1 + 效果原子参数契约（触发器/形态/必填/范围/枚举）+ 词条池落点 |
| `schema:progression` | 经验曲线、遗物稀有度调度 |
| `schema:difficulty` | 难度曲线 |
| `schema:intermission` / `schema:stagePlan` | 波间与阶段导演（含验证波奖励星级上限） |
| `schema:crossDomain(...)` | 神池 / 遗物 / 配方 / 波末奖励的跨域结构与引用 |
| `schema:tuner` | 调参元数据：路径唯一、指向真实数值、范围合法、枚举有候选 |

### 跨引用层
| 检查 | 规则 |
|---|---|
| `reference:idUniqueness` | **命名空间内** id 重复 → error；**跨命名空间**同名 → warning（见 §4 的口径说明） |
| `reference:textKeys` | 卡牌 / 进化分支 / 神的 `textKey` 必须解析到文案节点；遗物的 `${textKey}.name`/`.desc` 与调参的 `labelKey`、分组标题必须是非空字符串 |
| `reference:textOrphans` | `texts.relics` 与 `texts.tuner.params` 中没人引用的条目 → warning |

### 语义层
| 检查 | 规则 |
|---|---|
| `semantic:affixSinkConsumers` | 每个 `CardAffixStatKind` 必须有 `globalConsumer` 或 `scalingTargets`——**这是"最大生命词条掷得出、没人消费"那类 bug 的复发防线**；同时校验 scalingTargets 引用的原子/参数在 `ATOM_CONTRACT` 里存在 |
| `semantic:bossWavesReachable` | Boss 波次必须是 `1..totalWaves` 的不重复整数（加载器本会**静默丢弃**越界值） |
| `semantic:validationRewardKinds` | 验证波奖励的 kind / star / count / typePolicy；`kind` 缺失 → warning（加载器本会静默补成 `wildcard`） |
| `semantic:economyInvariants` | 入装门槛 ≤ 最高星级；手牌格/装备格 ≥ 1 |
| `semantic:activePoolFeasibility` | 不属于任何神卡池的正式卡 → warning（本局永远抽不到） |

> **两处"静默"被显式化**：越界 Boss 波次与缺失的奖励 kind，此前都会被加载器悄悄纠正。管线把它们提升为 error / warning，让作者知道自己写的和实际生效的不一致。

## 2. 写回端点契约（dev only）

三个端点都只在 `vite` dev server 上注册（`apply: 'serve'`），**不进生产构建**。请求体一律 JSON，响应一律 JSON。

### `POST /__config/domains`
返回可写域 → 目标文件的映射。

```jsonc
// → 200
{ "ok": true, "domains": { "skills": "src/config/base/skills.json", "texts": "src/data/texts.json", … } }
```

### `POST /__config/validate` — 只校验不写
```jsonc
// 入参 A：不带 domain = 校验磁盘上的当前配置
{}
// 入参 B：带 domain = 校验"把该域换成 data 之后"的整套配置
{ "domain": "gods", "data": { "version": "0.1.0", "gods": [ … ] } }
// → 200
{ "ok": false, "report": { "ok": false, "issues": [ … ], "checks": [ … ], "variants": [ { "variant": "dev-short", "report": { … } } ] } }
```

### `POST /__config/write` — 先校验后写
```jsonc
{ "domain": "tuner", "data": { … } }
```
| 响应 | 含义 |
|---|---|
| `200 { ok, path, report }` | 校验通过并已落盘（规范格式） |
| `422 { ok: false, error, path, report }` | **校验未通过，未写盘**；`report.issues` 给出逐条定位 |
| `400 { ok: false, error }` | 请求本身有问题（未知域、缺 `data`、body 不是 JSON） |

流程：`装配 base+variant → 用 data 覆盖该域（并重放 variant 对该域的覆盖）→ 三层校验 → 通过才 stableJson 落盘 → 让 Vite SSR 模块图失效`。

**已核实的行为**（本地 dev server 实测）：
- 原样写回 `economy.json` / `tuner.json` → 200，文件**字节未变**（零 diff）。
- 神池引用不存在的卡 → 422，文件未被改写，报文精确到 `$.gods.gods[0]`，并额外警告 `chainLightning` 会变成抽不到的孤儿卡。
- 调参路径指向不存在的字段 → 422，文件未被改写。
- 未知域 → 400。

### 复用同一套写盘工具的既有端点
`/__calibration/export`、`/__tuner/preset`、`/__telemetry/session`、`/__telemetry/baseline` 保持原有契约，但已改为共用 `postJson` + `writeRepoFile` + `stableJson`——四处重复的「收 body / try-catch / 手写 JSON 响应」样板消失，写盘格式也随之统一。

## 3. 编辑器 v1 应该怎么调用

1. 启动时 `POST /__config/domains` 拿到域清单，按域读取对应 JSON（直接 `fetch` 静态文件即可，dev server 会原样提供）。
2. 表单每次改动后 `POST /__config/validate { domain, data }`，把 `report.issues` 按 `domain` 分组渲染到右侧校验面板；`level: 'warning'` 不拦保存，`'error'` 置灰保存按钮。
3. 保存时 `POST /__config/write { domain, data }`。**不要**自己序列化后再写——端点会用 `stableJson` 统一格式，编辑器只需要传结构化对象。
4. 拿到 200 后刷新页面即可让运行时读到新配置（配置单例在启动时装配，一局内不热更——见交付说明 §3.2）。
5. 提交前跑 `npm run validate`；CI 也跑同一条命令。

**不要绕过端点直接写文件**：那会跳过校验，也可能写出非规范格式的 JSON，破坏后续 diff。

## 4. 本轮暴露并处理的既有问题

| 现象 | 处理 |
|---|---|
| 6 条配方的 `id` 与其产物卡 `id` 同名（`frozenThunder` 等） | **规则改了，不是数据改了**。原先写的"所有 id 全局唯一"是错的模型：配方 id、卡 id 分属不同查找表，且"配方以其产物命名"是既定约定。现口径：命名空间内重复 = error；跨命名空间同名 = warning，且配方↔自身产物这一对**豁免不报** |
| 10 个配置文件不是规范 JSON 格式 | 已执行一次 `npm run format:config` 规整。代价是 `tuner.json`（+1953 行）与 `relics.json`（+576 行）展开成一键一行，可读性下降；收益是工具写回与手工编辑字节一致、diff 只反映真实改动。这两个文件从此以工具维护为主，判断是划算的 |

**没有为了让命令通过而放宽任何规则**：唯一改动的规则是上面那条被证明建模错误的 id 唯一性口径，且改后仍会以 warning 形式提示同名。

## 5. 已知边界与后续

- **`stableJson` 默认不排序键**：保留源文件键序（`id` 在前、`effects` 在后这类有意义的排布）。`sortKeys: true` 可选，当前无人使用。排序会制造巨量无意义 diff，故不设为默认。
- **写回后需刷新页面**：配置单例在应用启动时装配，一局内不热更。端点只让 SSR 模块图失效（保证下次校验读到新内容），不主动触发客户端 reload。
- **variant 覆盖的重放**：候选数据写的是 `base/<domain>.json`，因此校验时会按 loader 语义把每个 variant 对该域的覆盖重新合并上去。若将来注册了更多 variant，`validate` 与写回会自动多跑几遍，无需改代码。
- **`texts` 域**：已纳入可写域，但 `texts.json` 结构本身尚无 schema 校验（只校验"被引用的键必须命中、不许有孤儿"）。做文案编辑器时需要补一层结构校验。
- **未纳入**：`presets/`、`telemetry/`、`docs/` 下的产物文件不属于配置域，仍由各自专用端点写。

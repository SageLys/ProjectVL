## §0 通用规则

1. 每卡进化树固定为：1★基础 → 2★数值 → **3★分叉(A/B/C)** → **4★公共**（对 3★ 分支同构放大 + 可选公共绑定）→ **5★分叉(A/B/C)** → **6★公共终态**。3★/5★ 分支独立组合，效果全部叠加。
2. 旧卡改造映射：现有 3★ core → 3★分支 A 的基础；现有 5★ dual 增量 → 5★分支 A；现有 6★ transform → 6★ 终态；现有 `amplifyAxis.params` → 4★公共放大参数。B/C 分支为本表新增。
3. 消耗态：旧卡沿用现有 anchors(1/3/6)；新卡按本表"消耗"行设计（placement 均为 point，interpolation linear）。
4. 词条池：每卡 `count: 2`，候选 3–4 条；表内格式 `stat(min~max/step)`；consumableDuration 统一占位 5s。
5. 每神必须覆盖：直接伤害 / 范围或弹道 / 控制 / 防御容错 / 资源成长；2 张身份锚点；≥1 个对其他神开放的乘法接口（见各神"接口"行与 §4 矩阵）。
6. 文案键：`gods.<godId>`、`cards.<cardId>`、`evolution.<cardId>.<optionId>`；中文名为文案基准。

## §8 协同性总则（实装与验收口径）

1. 全部效果可叠加：任何两卡装备态并存不冲突（沿用装备态多效果并行机制与 statusSystem 仲裁）。
2. 乘法接口清单：易伤（storm/plenty/winter 多卡）、受控增伤（winter）、灼烧易伤（inferno）、聚怪（bulwark decoy/taunt、plenty brand）、攻速与触发频率（storm overcharge、sanctum-C）、全局经济（plenty）。C8 的 `tests/skillCompatibility.test.ts` 扩展矩阵需覆盖每类接口至少一个跨神组合用例。
3. 控制类新卡全部服从现有控制预算/ccImmune/kbFatigue 仲裁，不得绕过。

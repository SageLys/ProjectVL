## 通用结构（七步，来自 `求职作品集转化指南` §5.3）

```
标题：问题式，不用「XX系统设计」这类功能式标题

1. 原始问题 —— 观察到的具体现象，不要跳到方案
2. 设计分析 —— 为什么会发生，涉及哪些变量
3. 备选方案与取舍 —— 真实考虑过的选项，放弃了什么、为什么
   （当时没认真比较过就如实写「未系统比较」，不要事后编造）
4. 实现方式 —— 流程图/配置字段/数值规则/状态机，贴关键片段不贴全部代码
5. 验证与结果 —— 测试方法 + 版本对比 + 数据变化，每条带强度标签
6. 遗留问题 —— 当前仍未解决的部分
7. 反思 —— 方案边界在哪、下一版怎么处理、哪个原假设被推翻了
```

# TASK-4 · L6 AI 工作流章节

## 素材

- 仓库根目录 68 份 `codex-prompt-*.md`——**这本身就是任务拆解 + 验收标准的记录**，是这一层最好的原始素材
- `docs/project-retrospective/` 下的归属核查结论

## 结构

1. **问题**：一个人 + 有限时间，如何在 29 天内把 11 张卡的原型扩到 60 卡 5 神的可玩系统
2. **工作流**：设计目标定义 → 任务拆解 → Prompt 编写（含验收标准与禁止副作用）→
   AI 生成 → 人工审核 → 自动校验（`npm run validate` + `vitest`）→ 集成 → 真人试玩 → 修订
3. **AI 承担的**：按 Prompt 实现代码、编写部分测试与工具、生成技术文档、机械性重构与批量内容落地
4. **我承担的核心责任**（**这一节必须写满，是防止「AI 主导」印象的关键**）：
   玩法定义、真人试玩与体验判断、问题诊断、方案拍板、Prompt 编写与实现边界界定、版本验收、优先级排序
5. **质量控制手段**：三层配置校验、固定 seed 黄金回放、设计指纹夹具、跨引用与语义校验
6. **实际收益**：**不编造百分比**，改用「被替代的具体步骤」描述。
   参考句式：「把原本需要手工同步 Excel 与代码的流程改成双向脚本，人工只需最后确认差异行」
7. **两个 AI 出错并被我拦下的真实案例**（这一节是全章最有说服力的部分）：
   - ChatGPT 报了一批数值词条缺陷，核实后发现一半是假的——它说某张卡的 heal 词条失效，
     实际上全量 `skills.json` 的 `affixPool` 里根本没有任何卡带 heal
   - 它断言致命命中不触发 `onHit`，也是错的
8. **一条更高阶的发现**（建议单独成段，这是差异化最强的一点）：
   > 「代码层面我一直在核。但最近我发现叙述层面也需要核。我让人把十份 AI 生成的项目复盘报告
   > 和我的原始聊天记录逐字比对，抽查了 81 处第一人称叙述，发现 4 处错误 4 处夸大。
   > 共同模式是 AI 把自己提出的方案写在『你提出』后面，不做归属切分。
   > 最有意思的是我自己读那十份报告时完全没察觉——因为那些方案确实是我采纳并执行了的，
   > 只是不是我先提出的。『我采纳并执行了』和『我提出了』差别很大，而这个差别靠回忆是发现不了的。」

## 好/坏表述对照（写作时对照检查）

| 不要写 | 改写为 |
|---|---|
| 「用 AI 生成了全部技能配置」 | 「定义了技能数据契约（8 触发器 × 38 效果原子），用 AI 批量生成 60 张卡的 JSON 配置，自己写校验脚本核对边界条件」 |
| 「AI 帮我提效 80%」 | 「把原本需要手工同步 Excel 与代码的流程改成双向脚本，人工只需最后确认差异行」 |
| 「AI 分析报告显示 XX」 | 先自己跑一遍可复现命令核实，再引用 |

# 面试准备自查（能力项，不是交付物）

1. 能否 30 秒介绍这个项目？

## 速览卡正文（一屏）

### 项目定位

竖屏 360° 合成塔防可玩原型。中央「清醒炮台」自动迎击四面涌来的敌人，
玩家的全部操作是**拾取掉落卡 → 合成升星 → 装备构筑 → 关键时刻牺牲装备释放主动效果**。
单局 10 波，按选择期 / 构筑期 / 验证期三阶段编排敌潮与掉落。

### 我的职责

核心玩法定义、战斗机制设计、数值方向、交互规则、真人试玩、问题诊断、方案拍板、
Agent 任务规格编写与版本验收。**代码由 Codex / Claude Code 等 AI Agent 依据我的设计规格实现**，
我负责审查结果并决定后续迭代方向。第三方协作者依据我的规则与配置契约独立完成了跨引擎移植（见附注）。

### 关键设计（三条）

1. **单局三阶段结构**——把整局从「线性递增」改为「选择期建立认知 / 构筑期承受最高压力 /
   验证期关闭普通掉落、只检验构筑」。同时把掉落从「按击杀概率」改为时间令牌桶，
   切断「DPS 越高掉落越多 → 强 Build 反而操作负担更重」这条反向惩罚链。
2. **可拒绝的悬赏契约**——把随机金色精英改造成信息前置的主动风险决策：接受前展示确定奖励、
   可无惩罚拒绝、接受后从对应方向生成一组强化敌群、任意一名突破则整组失败无奖励、
   炮台优先索敌赏金目标但近身威胁可覆盖优先级。
3. **控制的系统边界**——高星冰冻 + 击退构筑会让敌人被推出射程、炮台丢失目标、战斗变成无威胁的等待。
   两轮「加抗性」的局部修复失败后，改为三层结构性方案：射程限位（不能把射程内的敌人推出射程）、
   全局控制预算（场上必须保留至少 2 名自由推进者、受控上限 60%）、单次潜力封顶
   （冻结 2.5s / 眩晕 1.5s / 击退 120 的绝对上限）。

### 代表性迭代（一条，带前后对比）

| | 迭代前 | 迭代后 |
|---|---|---|
| 依据 | 9000 + 18000 + 300 = 27300 局蒙特卡洛仿真，文档指标全部达标 | 一次约 90 秒的真人试玩，直接否定整个版本 |
| 诊断 | —— | 屏幕长期空、敌人缺乏存在感、玩家几乎无事可做、数值达标却完全不好玩 |
| 动作 | —— | 主动回退到 P3 完成态，废弃 P4 / P4.1 / P5 的数值与代码结论，把真人验收设为后续阶段唯一出口 |
| 结果 | —— | 前 90 秒同屏中位数 3–7 → 过冲到 14 → 回落到 6–7，高压力移向中后期（46 份遥测可回溯） |

**形成的设计原则**：自动仿真只能判断配置是否符合假设，不能判断假设本身是否好玩。

### 完成度与限制

设计验证型可玩原型，非完成平衡的商业 Demo。当前已知未闭环：
验证期（波 9–10）压力分布结构断裂、波尾冲刺未达设计意图、中后期掉落过期与满手拒收较严重、

## 数据速览 4 · 主炮融合：一个由字典序决定胜负的 bug（★★★★★）

| | 修复前 | 修复后 |
|---|---|---|
| 两张 beam 叠装 | pierce(1.0) + sentinel(0.8) → 0.8 × 0.75 = 0.6，**比单装 pierce 弱 40%**，赢家是字典序靠后的那张 | 取 damageRatio 最强者、参数成套采用、不打折 |
| mortar 衰减基准 | 全局混合下标（「光束 + 一张 mortar」时 mortar 被误伤） | 组内位置（mortar 永远是组内第 0 位） |
| 半径配置语义 | `radiusMul: 0.6`（看起来六折，实际面积 0.6² = 0.36） | `areaMul: 0.36`（配置直接说人话） |
| 融合爆炸成长 | 只继承 damage → 开局 1.38× 单调衰减到 ≈1.0 | 全额继承 damage / fireRate / multi，impactShare 从周期预算切固定比例 → 三档成长下恒 1.35× |

**为什么这张好**：它区分了两类完全不同的问题——「数值没调好」和「设计有确定性错误」。
字典序决定强弱不是平衡问题，是设计错误。整条链在 GitHub PR #5 上可以逐行核对。

⚠ **使用限制**：我的贡献是三层追问与两处拍板（全额继承 + 目标 1.35×），
具体建模与标定由 AI 完成。讲成「我追问出了这个问题并拍板了继承策略」，
**不要**讲成「我设计了正交轴分解」。

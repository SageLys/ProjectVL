### 1.1 新增能力（每条列明契约、融合语义、校验规则、服务产物）

**C1 `summon.chainRelay: boolean`**（晶脉传导 / 雷枢方阵）
中继召唤物并入 `chain` 的搜索候选；链跳到中继体不造成伤害、不衰减（`relayRetention: 1.0`），并以中继体为新起点继续搜索敌人；`relayDamageBonus?: number` 每经一座中继，后续跳伤害 +N%（封顶 `relayBonusCap`）。融合：中继体属实体，无跨卡仲裁。校验：`chainRelay` 只允许出现在 `recipeOnly` 产物的 summon 定义；链经中继的循环保护（同一中继一次链最多入选 1 次）。

**C2 `summon.onDeath: EffectDef[]`**（永固圣域 / 寒棺尖碑 / 冰像阵 / 晶脉传导）
召唤物死亡或到期时，按**其坐标**执行效果表。只允许坐标类原子（burstDamage/aoeOnHit/freeze(radius)/slow(radius)/zone/knockback/掉落类）；校验器禁止直接单体原子（红线 V8 同源）。现有 `explodeDamageMul` 保留为兼容糖并在内部转译为 onDeath。

**C3 通用计量条 `charge`**（电容堡垒 / 罪火迫击 / 福祸相生 / 常燃火山）
绑定级参数：`charge: { by: 'shieldAbsorb'|'thornsDamage'|'breach'|'killWithSource', perEvent: number, max: number, releaseAt: 'full'|'onShieldBreak'|'interval', interval?: s }`。释放时执行绑定效果表，`chargeCount` 可经 `perChargeMul`/`perChargeAdd` 缩放效果参数，释放后清零。HUD 复用进度条样式显示计量。融合：每(卡,绑定)独立计量，不跨卡合并。校验：`by` 枚举合法；释放效果表过 V8；`max` 必填。

**C4 `requiresStatus` 数组（AND 语义）**（蒸汽爆裂 / 霜雷云 / 盈电金流 / 余烬收成）
`requiresStatus: StatusId[]` 表示目标须同时持有全部状态；单值字符串向后兼容。fallback 通道语义不变（不满足→基础结算）。校验：数组元素合法且去重、长度 ≤2。不做 OR 语义（YAGNI）。

**C5 `extraDrop.secure: true`**（回春霜露 / 余烬收成）
生成的掉落走 validation 奖励既有 `secure` 通道（不过期、结算窗保护）。校验：仅 `recipeOnly` 产物可用。

**C6 参数动态缩放 `scaleBy` 枚举扩展**（燃烧护城河 / 丰饶圣林 / 盈电金流 / 霜火榴弹 / 回春霜露）
复用「按在场状态数缩放」通道，统一为 `scaleBy: { source, param, perUnit, cap }`，source 枚举扩展：`concurrentStatus:<id>`（已有）、`shieldTier`（当前 shield 剩余档位）、`summonLevel`（C8 等级）、`statusStacks`（目标身上冻结层数等）、`controlledInAura`（光环内受控数）。校验：source 合法、cap 必填。

**C7 弹道尾迹区 `trailZone`**（天罗电网 / 贯日）
`pierce`/弹道原子新增 `trailZone: { effects: EffectDef[], width, duration }`：弹道飞行路径生成条状区域，区域内按 zone tick 语义执行 effects（可内嵌 `vulnerable`/`dot`；内嵌 dot 遵守「zone 内 dot 不挂状态」既有事实）。校验：effects 过 V8；仅产物可用。

**C8 事件强化召唤物 `summonBuff`**（丰饶圣林 / 根脉织网）
效果原子：`summonBuff: { target: 'all'|'nearestToPoint', kind: <本卡召唤物种类>, params: Record<param, '+n'|'*n'>, capLevels }`。按等级记录在召唤物实例上，跨波保留（根脉永久、金树波内）。校验：kind 必须是本卡声明的 summon 种类；capLevels 必填。

**C9 传染通道扩展 `maxTargets` / `excludeStatus`**（悬赏烙印；金印尾端复用）
既有「aoeOnHit 无伤害传染」通道加两个参数：`maxTargets: number`（只选最近 N 个）、`excludeStatus: StatusId`（跳过已带状态者）——实现烙印「死亡即接力到最近未标记敌人」。校验：maxTargets ≥1；excludeStatus 合法。

### 1.2 通用红线（全部沿用）

onKill/onBreach 按事件坐标；绑定内不重复取最大/覆盖原子；`requiresSource` ∈ {weapon,chain,dot}；「每命中各触发一次」只走贯穿/分裂；产物身份原子只许来自 `sourceGods` 两神（V6 白名单）；**禁止为单张产物在核心层写 if**——若实装中发现某能力只剩一个使用方，回本表把它并入邻近通用能力或降级为参数，不得偷偷内联。

## 2. 产物通用字段规则（25 张统一）

1. **stars**：只有 `stars['6']`（tier `transform`），绑定见 §3–§5。无 `evolutionTree`、无 4★ amplify（`amplifyAxis.description: "配方终态不再放大"`，params `{ terminal: "+0" }`，沿旧产物惯例）。
2. **identityContract**：每卡一句话（§3–§5 给出）。
3. **消耗态**：产物只以 6★ 存在，anchors `1`/`3`/`6` 三档**同值**（类型要求三档齐全），内容＝该产物核心动词的一次性释放（§3–§5 每卡一行）。
4. **affixPool**：沿用 `primaryGod` 神系模板（35 卡表 §0.4），count 2。
5. **双神字段**：`primaryGod`＝锚点方、`sourceGods: [可变方, 锚点方]`、配方 `recipeId` 关联；只用于图鉴/遥测/工作台矩阵视图。
6. **强度口径**：对标 32 点自升 6★。占位数值给「明显可感但不夸张」档：产物主输出 ≈ 单张 6★ 材料的 1.2–1.5 倍当量 + 1 个净空槽收益；E4 冒烟脚本按 §6.3 门槛卡。
7. **文案**：`cards.<id>.name`/`overview` 照 §3–§5；hand/equip short 按 35 卡表 §0.5 模板（只有 6★ 档）；里程碑只有 `6`（fx `transform`）；「灰盒占位」字样全部清除。
8. **立即可见**：每卡的「首个专属表现」必须在进化完成后 ≤5s 内可触发（§6.2 有断言）。

## 3. B1 · 同神升华（5 张）

> 批次目标：先立五神毕业形态。B1 全部验收（校验绿 + 专项测试 + 黄金回放无漂移）后才开 B2。

### 3.1 天罗电网 `stormLattice`（storm · projectile · [projectile, domain]）

**identityContract**：贯穿雷矛的飞行路径留下导电雷轨，轨上敌人持续感电。
**绑定**：
1. `passive` → `pierce` 换形（全轴贯穿，`damageRetention 0.85`）＋ `trailZone { effects:[vulnerable(2.5s)], width 26, duration 4s }`（C7）
2. `onHit + requiresStatus:'vulnerable'` → `burstDamage { radius 60, damageRatio 0.8 }`（贯穿逐个兑现；fallback 0.3）
3. `interval 2s` → `chain { targets 2, bounces 3, damageRetention 0.8, spreadStatus:'vulnerable' }`（轨网自动链）

**消耗态**：沿炮台→落点轴一发巨型雷矛＋全程雷轨。**overview**：把战场织成一张会咬人的电网。
**Boss**：Boss 常驻感电 → 兑现每发稳定触发；雷轨叠于 Boss 行进线＝持续增伤走廊。
**测试**：贯穿 5 个感电目标断言 5 次 burstDamage；trailZone 生成与 4s 过期；轨内敌人获 vulnerable。

### 3.2 冰河世纪 `glacialEpoch`（winter · domain · [domain, control]）

**identityContract**：周期从核心向外推进冰川锋面，扫过者减速、叠冻、被推离。
**绑定**：
1. `interval 4s` → 扩张锋面环（复用扩张环通道）：`slow 0.35` + `freeze 层 +1` + `knockback { distance 40 }`，环从 r60 推至 r260
2. `onHit + requiresStatus:'frozen'` → `burstDamage { damageRatio 1.5 }`（碎冰；fallback 0.4）
3. 锋面对高击退抗性目标（含 Boss）：不推，改叠双倍冻结层（C6 `statusStacks` 通道的替代收益写法）

**消耗态**：立即从核心推出一道全强锋面。**overview**：整个屏幕是一记慢速重锤。
**Boss**：见绑定 3（抗性替代收益）。
**测试**：锋面环推进与命中判定；knockbackResist=1 目标获 2 层冻结；frozen 目标碎冰倍率。

### 3.3 常燃火山 `volcanoCore`（inferno · domain · [domain]）

**identityContract**：常驻火山周期喷发熔弹铺设子火场，火场击杀为喷发蓄能。
**绑定**：
1. `onWaveStart` → 火山 zone（dot，radius 90，核心前方 240px，整波持续）
2. `interval 3.5s` → `mortarMorph` 喷发（radius 80，damageRatio 1.4，落点＝最密敌群）＋子火场 zone(dot)（radius 70，5s）
3. `charge { by:'killWithSource(dot)', perEvent 1, max 3, releaseAt:'full' }` → 满 3 点立即追加一次喷发（C3）
4. `onHit` → `dot`（直接灼烧，V9 供给）＋`onHit + requiresStatus:'dot'` → `burstDamage { 0.5 }`（fallback 0.15）

**消耗态**：落点立起一座临时火山（整段喷发序列）。**overview**：火养火，越烧越勤。
**Boss**：喷发落点优先 Boss 队列；dot 全程有效。
**测试**：火场击杀 3 次触发追加喷发；火山 zone 波内不消失；V9（绑定 4 供给 requiresStatus:'dot'）。

### 3.4 永固圣域 `aegisCitadel`（bulwark · defense · [defense, domain]）

**identityContract**：壁垒实体化为环形圣墙，塌墙即反击。
**绑定**：
1. `onWaveStart` → `summon { kind:'wall', count 4, 环形均布, hp 占位, blocker }`，onDeath: `[burstDamage{radius 90, 1.2}, knockback{40}]`（C2）
2. `passive` → `breachReduction 0.15`
3. `interval 9s` → 补墙 1 段（场上上限 4）

**消耗态**：立即在核心外圈补满圣墙。**overview**：看得见的壁垒，塌了也要咬一口。
**Boss**：墙体阻挡迟滞 Boss；破墙触发爆发。
**测试**：墙体阻挡碰撞；塌墙坐标爆发（不引用尸体）；上限 4 不超；断言同局无 aegis（材料已消耗，novaOnBreak 类互吃不存在）。

### 3.5 丰饶圣林 `goldenGrove`（plenty · economy · [utility, domain]）

**identityContract**：拾取点长出金树，金树标记敌人并持续产出。
**绑定**：
1. `onPickup` → `summon { kind:'goldenTree', 上限 3, 位置＝拾取坐标 }`；树自带 `interval 4s → focusPriority(1)` + `interval 6s → extraDrop { chance 0.5, 树冠内 }`
2. `onKill + requiresStatus:'brand'` → `summonBuff { target:'nearestToPoint', kind:'goldenTree', params:{ radius:'+10', dropChance:'+0.05' }, capLevels 5 }`（C8）

**消耗态**：在落点直接种下一棵满级金树（波内）。**overview**：经济长在地上，去浇水就行。
**Boss**：树持续标记 Boss（集火加成全程）；Boss 波掉落由树供给。
**测试**：拾取种树上限 3；赏印击杀升级最近树、5 级封顶；树的标记与掉落节拍。

## 4. B2 · 跨神第一方向（10 张）

> B1 全部验收后开工。每张实装后与其反向卡的设计稿并排复核方向性（配方方案 §8.2），实装若造成两方向趋同，先改本方向再继续。

### 4.1 霜雷云 `thunderRime`（winter · domain · [domain, control]）＝ stormcall + frost

1. `passive` → 移动 aura（跟随最密敌群，radius 110，`slow 0.3`）
2. `interval 2.5s` → 云内落雷：对云内最近 2 目标 `burstDamage { radius 55, 1.0 }` + `vulnerable(2s)`
3. 落雷对 `requiresStatus:['slow','vulnerable']` 目标 → 追加 `freeze 层 +1` 且倍率 ×1.5（C4；fallback＝基础落雷）

**Boss**：云锁定 Boss 落雷全额；冻结抗性由倍率补偿。
**测试**：云跟随逻辑；双状态判定 AND；单状态 fallback。

### 4.2 引雷火种 `emberSpark`（inferno · domain · [domain, control]）＝ staticSurge + scorch

1. `onHit` → `dot(3s)`（V9 供给）
2. `interval 2s` → forEachStatusTarget(dot, max 4)：以目标坐标起 `chain { targets 1, damageRatio 0.5, spreadStatus:'vulnerable' }`（复用）

**测试**：4 个灼烧目标各起一条链；双持死亡强化；链不发 onHit（既有事实回归）。

### 4.3 电容堡垒 `voltBastion`（bulwark · defense · [defense, control]）＝ galvanicWard + aegis

1. `onWaveStart` → `shield { absorbHits 3 }`
2. `charge { by:'shieldAbsorb', perEvent 1, max 5, releaseAt:'onShieldBreak|full' }` → 放电风暴：`chain { targets 2+chargeCount, spreadStatus:'vulnerable' }` + `stun 0.3s`（C3）

**消耗态**：立即满充并释放一次放电风暴。**overview**：挨的每一下都在充电。
**Boss**：对 Boss 的 stun 改为倍率 +50%（抗性替代）。
**测试**：吸收计数→链数缩放；破盾与满层双释放口径；计量 HUD。

### 4.4 盈电金流 `ampereFlow`（plenty · economy · [utility]）＝ overcharge + harvest

1. `passive` → `focusPriority { 优先 vulnerable 目标 }` + `dropRateMul scaleBy { source:'concurrentStatus:vulnerable', perUnit +0.08, cap +0.4 }`（C6）
2. `onHit` → `vulnerable(2.5s)`
3. `onKill + requiresStatus:['brand','vulnerable']` → 死亡坐标 `extraDrop { chance 1.0 }`（C4；单状态 fallback chance 0.35）

**消耗态**：全场感电并立即结算一波掉落。**overview**：战场密度就是汇率。
**Boss**：Boss 双持＝稳定高掉率窗口。
**测试**：掉率随并发数阶梯；双持击杀必掉；封顶生效。

### 4.5 霜火榴弹 `rimeShell`（inferno · projectile · [projectile, control]）＝ frozenBulwark + splitBlast

1. `onHit` → `freeze 层 +1 (stacksToTrigger 3)` + `split { count 3, damageRatio 0.5 }`，弹片附弱 `dot`
2. 弹片 `onHit + requiresStatus:'frozen'` → `burstDamage { 1.8 }`（fallback 正常弹片伤害）
3. 对冻结抗性目标（Boss）：按冻结层数每层 +25% 弹片伤害（C6 `statusStacks`）

**消耗态**：落点一发巨型霜火弹（冻结＋二段爆）。**overview**：先钉住，再引爆。
**测试**：弹片各自 onHit（既有事实）；frozen 弹片倍率；层数缩放。

## 6. 测试矩阵与验收

### 6.1 每张产物的最小断言集（25 × 各 3–5 条，§3–§5 已逐卡给出）

统一另加：绑定通过 V6 白名单（身份原子 ∈ sourceGods 两神）＋V8＋V10＋V11；`recipeOnly` 池隔离回归；进化事务落位后产物绑定立即生效（对账链）。

### 6.2 「立即可见」自动断言

每张产物定义一个 `signatureEvent`（如 stormLattice=首条雷轨生成、voltBastion=计量条出现），测试以固定 seed 执行进化后 5s 内该事件必须出现（遥测流断言）。

### 6.3 E4 数值冒烟门槛（占位，可调）

固定 seed 三场景（波 7 密集 / 波 9 验证 / 波 10 Boss）脚本对比：装备产物 vs 双 5★ 材料 vs 单 6★ 材料。门槛：产物核心贡献 ∈ [1.1, 1.8]× 单 6★ 材料当量；越界者只调本表占位参数，不改结构。同神/跨神各抽 2 张人工试玩记录（配方方案八审 ⑧ 复核）。

### 6.4 批次验收顺序

E0 引擎（含 §1.0 复用自检）→ B1 → B2 → B3，每批：校验器绿 → 专项测试绿 → `npm test`/`npm run build` → 黄金回放非配方路径无漂移 → 提交。全部完成后 E4 冒烟 + 更新 `内容设计工作台` 矩阵视图的产物状态（灰盒→正式）。

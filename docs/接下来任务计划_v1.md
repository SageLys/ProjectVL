## 1. 模块三分类清单（Unity 与配置固化的分类基线）

Unity 移植与契约冻结都以这张表为准。

### 稳定（可冻结，Unity 直接移植其规则）
- `core/updateGame.ts` 单帧编排与系统执行顺序（见 §Unity 交付说明的核心更新契约）
- `GameEvent` 事件流（表现副作用的唯一出口）
- 效果解释器**架构**：8 触发器 × 34 原子、passive 聚合、消耗态落点释放（**机制稳定；参数契约已强化，持续核对实际消费点**）
- `statusSystem` 状态系统与控制预算/冲突仲裁
- 伤害结算 `damageSystem`、合成/装备/掉落/波次/Boss 核心规则
- 配置六域 + `variant` 深合并加载（`config/loader.ts`）
- `AFFIX_SINKS` 词条契约（`config/affixSinks.ts`）——已是单一权威契约的样板

### 实验（较新、验证较浅，Unity 一期先不碰，等切片扩张阶段再纳入）
- 神池/构筑系统（C 系列，近期主线）
- 单卡进化树、卡间配方进化
- 波间决策队列 `decisionQueueSystem`
- 精英 Bounty 的具体数值与节拍
- **所有占位数值**：技能参数、经济曲线、难度曲线、xp 曲线

### 延后（schema 预留结构位，暂不实现——D2 及决策结论 §8）
- 卡牌融合数值词条（**本轮 T0.3 预留结构位**）
- 更多怪物机制（保证可由 属性+行为组件+触发+技能列表 组合即可）
- 手动瞄准（Unity 侧用 `ITargetProvider` 抽象预留）
- 局外成长（维持单一全局乘数占位）

## 4. 每个阶段"完成"的判据（Definition of Done）

- **S0 完成** = ①效果参数为判别联合、原子/词条定义单一来源；②tuner 元数据单源、遗物文案入 key、融合结构位已留；③核心更新契约规格书 + 一组固定 seed 黄金 fixture 存在；④`npm test`/`npm run build` 全绿。
- **S1-A 完成** = Unity 端到端跑通一条链路，并对同一 seed/配置重放出与黄金 fixture 统计一致的结果。
- **S1-B 完成** = `npm run validate` 一条命令做完 schema+跨引用+语义校验并给报告；tuner/文案改动可经中间件写回磁盘且 Git diff 干净。
- **S2 完成** = 能在表单编辑器里搜索/增删改卡牌·神池·遗物·配方·敌人·波次·文案·调参，实时校验、H5 预览、导出。
- **S3 工具链完成** = ①编辑器里原子/参数/域字段/卡名均有中文标签与解释（缺失回退英文不报错）；②`config:export-xlsx` / `config:import-xlsx` 双向无损幂等、导回全程经管线校验、skills 以关联多 sheet 表达；③卡/神文案可在各自模块内联编辑并双域写回；三者收尾 `npm test` / `build` / `validate` 全绿。
